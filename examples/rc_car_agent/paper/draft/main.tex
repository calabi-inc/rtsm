\title{Remembering Where Things Are: Measuring What Persistent Spatial
Memory Is Worth --- and What It Costs --- on a Physical Robot}

\begin{abstract}
Embodied agents built on foundation models typically perceive each task
from scratch: what the robot saw a minute ago is gone. We present
\rtsm{}, an open-source persistent spatial-memory layer that ingests
RGB-D and pose from a commodity phone, maintains a queryable 3D object
memory, and serves it to agents over REST/MCP\@. We measure the
task-level value of persistence with a pre-registered ablation on a
physical wheeled robot: an LLM-driven agent navigates to
language-specified objects either (a) by querying memory built from a
one-time scan, or (b) \emph{memoryless} --- restricted by a freshness
gate to observations less than 4\,s old, forcing visual search. The two
conditions share perception, pose, controller, and an image-verified
target-selection rule; only access to the past differs. Across
\todo{N} trials in five layouts, memory achieved \todo{TCR$_a$}\%
tape-measured completion versus \todo{TCR$_b$}\%, with median
time-to-arrival \todo{TTA$_a$}\,s versus \todo{TTA$_b$}\,s
(\todo{SPEEDUP}$\times$; one-sided Mann--Whitney $p=\todo{P}$ with all
failures censored at a common 900\,s horizon). The price of this
speedup is a one-time scan of \todo{SCAN}\,minutes per environment ---
amortized after roughly \todo{BREAKEVEN} tasks. Code, per-tick trial
logs, and the operating protocol are released.
\end{abstract}

\section{Introduction}

An embodied agent that surveyed a room a minute ago typically knows
nothing about it now. Vision-language-action policies and LLM-driven
agents are, with few exceptions, amnesic between tasks: asked to fetch
an object the robot has already seen, they search for it again. The
field has recently begun to name this gap from inside the policy:
retrofits add within-episode spatial state to VLA models so a
manipulator does not forget objects that leave its wrist camera's
view~\cite{AtlasVLA2026}. That is memory at the scale of seconds. The
complementary layer --- object-level memory that persists across tasks
and sessions, external to any policy, queried by the planner --- is
older folklore: everyone agrees a map should help, the way everyone
agreed retrieval should help language models. What converted that
folklore into an engineering discipline for LLMs was quantification.
This paper attempts the same conversion for robot spatial memory: not
\emph{whether} persistence helps, but \emph{how much}, and \emph{at
what cost}, measured on physical hardware.

We take the substrate position. \rtsm{} is an open-source layer that
ingests RGB-D frames and poses streamed from a commodity phone,
maintains a persistent 3D object memory (open-vocabulary labels,
embedding-based retrieval, per-object stability statistics), and serves
it to agents over REST and MCP interfaces. The agent consuming it here
is an LLM planner driving a small wheeled robot; nothing in the
interface is specific to either.

The design kernel --- the one thing we ask a reviewer to remember ---
is that our memoryless baseline is \emph{not a different stack}. It is
the identical stack with one bit masked: a freshness gate that permits
the agent to act only on observations less than 4\,s old, turning
navigation into visual search. Same detector, same pose stream, same
image-verified target-selection call, same controller, same hard total
time budget in both arms. Whatever gap the experiment measures is the
value of access to the past, and nothing else. Symmetrically, the cost
side is not hidden: the scan that builds the memory is timed, reported,
and amortized explicitly --- prior map-based systems treat it as free
sunk infrastructure~\cite{Liu2024}.

Contributions: (1) \rtsm{}, a persistent spatial-memory substrate
(phone $\to$ 3D object memory $\to$ REST/MCP), with a minimal
safety-argued agent harness (planner / navigator / monitor separation)
released as a runnable example; (2) a masked-access experimental design
for measuring the task-level value of memory on real hardware, with
tape-measure ground truth, pre-registered success criteria,
conservative censoring, and explicit scan-cost accounting ---
reproducible on consumer hardware (hobby chassis, phone, one consumer
GPU; the perception stack also runs on a \$250 edge module at reduced
rate); (3) E1 results: \todo{headline numbers}, with full per-tick
trial logs, the failure taxonomy that emerged, and the operating
protocol released.

\section{Related Work}
% Verified citation sweep 2026-08-10 + gap-analysis sweep 2026-08-12.
% Spot-check all 2026 arXiv ids before submission.

\textbf{Semantic mapping and object-centric scene representations.}
Object-level spatial representations are well established, from
object-oriented SLAM~\cite{SalasMoreno2013} through metric-semantic
scene graphs~\cite{Rosinol2020} to open-vocabulary variants that fuse
foundation-model features into 3D~\cite{Jatavallabhula2023,Huang2023}
or into object-centric graphs~\cite{Gu2024,Werby2024}. We do not claim
a richer representation: our substrate is deliberately flat ---
persistent object records with open-vocabulary labels and CLIP
embeddings, built from commodity phone capture and served over
REST/MCP\@. This literature largely evaluates map quality; what it
leaves unmeasured is how much a persistent map is worth to a downstream
agent at task level, which is the question our ablation answers.

\textbf{Object-goal navigation.} We adopt the ObjectNav framing and
success conventions~\cite{Batra2020} but change one assumption: the
environment was scanned before the episode, and that delta is precisely
what we measure. Modular map-based methods~\cite{Chaplot2020} transfer
to real homes far better than end-to-end policies (90\% vs.\ 23\%
real-world success in a six-home study~\cite{Gervet2023}; see
also~\cite{Ramrakhya2023}), motivating our modular stack; zero-shot
open-vocabulary methods~\cite{Gadre2023,Yokoyama2024} define the
strongest form of the memoryless regime our freshness-gated baseline
embodies. None of these comparisons isolates persistence as the sole
variable --- map, policy, and training regime change together.

\textbf{LLM agents and robot memory.} LLM planners grounded in
affordances~\cite{Ahn2022} or pre-built scene graphs~\cite{Rana2023}
established the paradigm we adopt, and OK-Robot~\cite{Liu2024}
demonstrated the specific phone-scan-to-CLIP-memory recipe end-to-end
--- but all treat memory as a fixed component inside a system
evaluation, so its individual contribution is never separated from the
pipeline, and the scan that builds the map is never priced.
Retrieval-augmented robot memories such as ReMEmbR~\cite{Anwar2024}
evaluate question answering over episodic stores rather than task
outcomes. Text-world agent-memory benchmarks~\cite{Maharana2024,Hu2025}
ask the right question --- does memory actually help the agent? --- and
our experiment supplies the embodied counterpart, where retrieval must
cash out as navigation success on hardware.

\textbf{Measuring the value of memory.} Memory's value cannot be
assumed: map-less agents solve realistic PointNav at 94\%
success~\cite{Partsey2022}, while ablating recurrence sharply degrades
blind navigation agents in simulation~\cite{Wijmans2023} --- the answer
is task-dependent and must be measured. The closest real-robot evidence
is GOAT's memory-reset ablation on a quadruped across nine
homes~\cite{Chang2023}, which established \emph{that} retained memory
raises success (83\% vs.\ 60\%) under step-budgeted SR/SPL; GOAT-Bench
analyzes memory in simulation with modality effects mixed
in~\cite{Khanna2024}; recent sim work quantifies pre-scan memory
against frontier exploration and prices index
construction~\cite{MemoryOverMaps2026}; MemoryVLA represents the
internal-memory camp that bakes persistence into policy
weights~\cite{Shi2025}. To our knowledge, no prior study combines a
pre-registered protocol, an identical-stack persistence ablation on
physical hardware, wall-clock time-to-arrival with censoring,
tape-measured success, and explicit amortization of the one-time scan
--- the ``at what cost'' half of the question. That combination is this
paper's niche.

\section{System}

\textbf{Memory substrate.} \rtsm{} receives RGB-D frames and 6-DoF
poses over WebSocket from a phone running an ARKit capture app. Each
frame passes through open-vocabulary detection and segmentation;
detections are embedded (SigLIP) and associated across frames into a
persistent object memory that tracks, per object, a 3D world position,
label hypotheses, hit count, a stability score, and the most recent
image crop; objects crossing a stability threshold are marked
\emph{confirmed}. Retrieval is embedding-based semantic search,
returning candidates with positions, scores, confirmation flags,
last-observed timestamps, and crops. Robot pose is passed through at
receive rate ($\sim$5\,Hz) stamped with a \texttt{frame\_epoch} counter
minted from the sender's session id: a new capture session means a new
world origin, and the epoch makes it impossible for a well-behaved
consumer to compare coordinates across that discontinuity silently. A
receive-time depth summary (``forward clearance,'' the 10th-percentile
depth of the central image band) is published alongside the pose and
serves as the wall guard for blind motion. Everything is served over
REST plus MCP; the agent below is a pure HTTP customer.

\textbf{Agent apparatus.} The agent accepts one HTTP goal (``go to the
teddy bear'') and runs a fixed three-role pipeline. The \emph{planner}
issues one semantic query and one forced-tool LLM call that must either
select a target id from the retrieved candidates or explicitly declare
\emph{no-match}; each candidate carries its latest camera crop, and the
prompt instructs the model to judge by the image --- automatic captions
are hints, not evidence (a necessity we learned in shakedown; \S\ref{sec:lessons}).
A hallucinated id is rejected and a deterministic top-1 fallback covers
API failure; which path ran is logged per trial. The \emph{navigator}
is deliberately simple: a proportional controller that re-aims at the
target's stored coordinates on every fresh pose, rotating in place when
heading error is large. The \emph{monitor} is the sole authority over
trial outcomes: arrival radius (0.40\,m), a hard total time budget,
bounded blind-driving on pose dropout, frame-epoch equality between
plan and execution, a pose-discontinuity heuristic, a drift bound, and
an obstacle rule --- measured clearance below 0.30\,m while the
believed target is still beyond 0.75\,m stops the trial with a
\texttt{blocked} verdict. Every trial writes an append-only JSONL log:
the plan record (candidates, chosen id, the LLM's stated reason,
coordinate age at plan time), one record per control tick, and a final
verdict.

\textbf{Safety, honestly.} Making a blind robot safe on a
$\sim$5\,Hz pose feed consumed a substantial fraction of the
engineering effort. Motion requires continuous software liveness (a
300\,ms firmware watchdog stops the wheels if the command stream dies);
held commands are re-sent as heartbeats faster than the watchdog
window; pose staleness beyond 2.5\,s forces a safe stop and aborts the
trial --- and if the last-known clearance was below 0.5\,m, the hold
commands zero rather than pushing blind. \todo{Finalize per campaign
reality: hardware e-stop configuration during trials (gamepad path
exists and is software-enforceable; sessions ran with operator
supervision + soft-stop console + watchdog).}

\section{Experiment Design}
\label{sec:design}

\textbf{Conditions.} Both arms receive the same goal phrasing and run
the same planner, navigator, monitor, and hardware. In condition (a),
\emph{memory}, the planner queries the full object store built from a
single pre-task scan. In condition (b), \emph{memoryless}, a freshness
gate restricts retrieval to objects observed within the last 4.0\,s ---
the agent may only act on what is currently in view, so it must search:
rotate-and-dwell sweeps ($12\times{\sim}30^\circ$ steps at the
calibrated turn rate), with a short forward relocation between sweeps.
The relocation is depth-guarded: the walk requires $\geq$0.6\,m of
measured clearance, and when blocked the searcher rotates step by step
and walks the first open direction --- the car turns away from walls
instead of grinding them. If the selection call judges every fresh
candidate a non-match, the rejected ids are masked and the search
\emph{resumes} (a memoryless agent that sees only wrong objects must
keep looking, not settle). The 4\,s gate is sized to one sweep-step
cycle so consecutive polls cover the whole rotation; it is widened in
practice by pipeline stamp latency ($\sim$0.5\,s, measured), and both
properties favor the baseline, i.e., are conservative against our
claim. Gated retrieval fetches deep (top-50 before gating) so memory
accumulated during the trial cannot crowd a currently-visible target
out of a top-$k$ list. Target selection is shared verbatim --- the same
image-verified forced-tool call over whichever candidate set the
condition permits --- so the comparison masks persistence, never
selection intelligence. Budgets are hard \emph{total} clocks of 900\,s
per trial in both arms, from command receipt: planning time counts
against (a) exactly as search time counts against (b), and the symmetry
removes any budget-shape confound.

\textbf{Venue and protocol.} One room, five layouts (five objects
re-placed per layout), start-to-target distances \todo{X--Y}\,m. Six
trial pairs per layout, strictly alternating conditions, with the
starting condition alternating across layouts and one repeated pair per
layout measuring run-to-run variance. Sessions end only at layout
boundaries; a fresh \rtsm{} process and scan per session. Layout
acceptance is two-sided: an object enters the campaign only if it is
retrievable from the scan \emph{and} detectable from robot height ---
rejected candidates are reported (transparent and low-contrast objects
failed; \S\ref{sec:lessons}) --- so object selection cannot favor the
memory arm.

\textbf{Ground truth.} After every trial the operator measures the
robot-to-object distance with a tape and photographs the final
position. Pre-registered success: monitor verdict \texttt{arrived}
\emph{and} tape $\leq$50\,cm (the 40\,cm commanded stop radius plus a
10\,cm centroid-projection and reading allowance); completion is also
reported at 40/60\,cm and under an any-verdict secondary definition.
The robot's own believed distance is reported separately and never as
the headline --- self-grading is circular.

\textbf{Statistics.} Time-to-arrival with \emph{all} failures (timeout,
abort, block, e-stop) censored at the common 900\,s horizon for a
one-sided Mann--Whitney test, with an arrivals-only sensitivity variant
and tie-corrected $U$. Trials within a layout share geometry, so
alongside the pooled $p$ we pre-specify a per-layout win table and an
exact one-sided sign test across the five layouts. We also report
search-vs-drive time decomposition for the baseline, terminal-error
decomposition ($|$believed $-$ tape$|$), the coordinate-age-at-plan
distribution for the memory arm, and scan cost with a break-even
estimate (scan minutes divided by per-task saving). Power, stated
prospectively (no pilot informs it): at $n=30$/arm, one-sided
$\alpha=0.05$, $\sim$80\% power requires $P(\text{memory faster})
\gtrsim 0.68$ --- the design detects only large effects, and smaller
effects will be reported as a null result.

\textbf{Provenance.} Every trial JSONL carries the config snapshot,
calibration id, git commit, planner path, RNG seed, memory-throughput
snapshots, and the chosen target's coordinate age at plan time --- the
map ingests continuously; the claim is persistence \emph{across tasks},
and the age distribution is reported rather than assumed.

\section{What It Took: a Failure Taxonomy}
\label{sec:lessons}

Running the ablation honestly required fixing the apparatus in ways we
believe generalize; we report them as findings.

\textbf{Captions lie; selection must be visual.} Open-vocabulary
captions for the correct object were frequently absurd (a teddy bear
labeled ``audio,'' then ``stage light''), and a label-only selection
rule rejected the true target mid-search. Attaching each candidate's
image crop to the selection call fixed this immediately: the model
recognized ``a clear teddy bear face despite the incorrect label.''
Selection over memory should treat captions as hints and pixels as
evidence.

\textbf{A memoryless agent needs permission to say no.} A forced-choice
selection over currently-visible candidates will settle for the best
wrong object (our baseline once drove 160\,s toward a smartphone when
asked for a teddy bear). The selection tool must have an explicit
no-match arm, and the searcher must mask rejected ids and resume ---
otherwise the baseline's failures are artifacts of the harness, not of
memorylessness.

\textbf{Freshness gates must be sized to pipeline physics.} Our
initial 2\,s gate sat inside the perception stack's real stamp latency
under load, making objects invisible \emph{while the camera stared at
them}. Gate windows must be measured against the deployed pipeline, not
chosen a priori.

\textbf{Color-channel discipline.} A single BGR/RGB swap at one
ingest boundary silently degraded every embedding, label, and stored
crop in the system for weeks (a red cola can rendered blue); retrieval
scores roughly doubled when fixed. End-to-end color validation ---
literally checking that a red object is red in the stored crop ---
should be a bring-up step for any perception memory.

\textbf{Blind motion needs a measured wall guard.} With no
proximity sensors, the searcher's relocation walks and the drive phase
both need the depth stream: require measured clearance before blind
walks, stop when clearance contradicts the believed target distance,
and never hold a drive command through a pose dropout near an obstacle.

\section{Limitations}

Single room and platform; static scenes (moved objects mean stale
coordinates --- by design, E1 measures retrieval value, not dynamics);
believed-frame path efficiency; $n{=}60$ with trials clustered by
layout (the layout sign test addresses this); a single unblinded
operator --- mitigated by pre-committed objective abort criteria,
evidentiary photos for every trial, per-condition abort counts, and no
discretionary exclusions; tape-TCR bundles terminal coordinate quality
with search success (quantified by the terminal-error decomposition;
TTA is the primary claim); memory plans may run on approach-refreshed
rather than scan-age coordinates (age logged and reported); the shared
LLM selection's failure modes are documented (\S\ref{sec:lessons}) but
not independently ablated; component-level map accuracy (fiducial
ground truth) is deferred to a full-length study. The scan was
performed by a human; autonomous scan acquisition is composable future
work, and the claim concerns the value of \emph{retained} memory, not
its acquisition policy. Persistence in \emph{changing} scenes ---
detecting that memory has gone stale --- is the natural sequel.
